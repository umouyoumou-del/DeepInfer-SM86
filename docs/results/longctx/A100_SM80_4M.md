## SM80 compatibility work

Triton's native E4M3 load/dot path requires SM89 or newer and raises:

```text
AssertionError: fp8e4nv data type is not supported on CUDA arch < 89
```

The fix is a software FP8 path:

- `deepinfer/moe/triton_fp8.py` detects the device capability and selects native
  FP8 on SM89+ or software decode on older devices.
- `deepinfer/moe/latent_mla_triton.py` passes a `uint8` view on SM80 and decodes
  E4M3 bytes inside the Triton kernel before the FP16 attention dot.
- `deepinfer/moe/latent_locate.py` has the same fallback for fused locate.
- SM89 keeps the native path; `DEEPINFER_TRITON_FP8=0/1` can force either path.
- `tests/moe/test_latent_mla_triton_fp8.py` compares the software decode path
  against the PyTorch reference on CUDA.

## Memory plan

The 16 GiB host limit rules out the 60 GiB pinned-host layout used for the
62 GiB long-context machine.  The A100 plan was:

```text
kv fp8 69.22 GiB; experts pinned;
gpu holds 3,830,167 tokens, host 366,185
```

Command used:

```bash
python scripts/needle_complex.py \
  --tokens 4194304 --model coder \
  --models-dir /root/models --meta-root /root \
  --positions dca --kv fp8 --near-window 98304 \
  --unpin no --workspace-gib 4 \
  --check-copies --self-check --value-pick \
  --out docs/results/longctx/complex_4m_sm80_varchain.json
```

Prefill took 1,101.7 s (18.4 min), with no OOM.

## VT exact-chain verifier

The first A100 4M run reached 20/21, 28/31.  VT expected five names but the
locate pass missed two assignment lines:

```text
VAR QHUJP = 14673
VAR INRCW = VAR AVCOU
```

The answer therefore stopped at `GHTAY, OKOSG`.  `value_pick` cannot recover
evidence that was never retrieved.

`deepinfer.moe.answer_check.var_chain_answer()` now parses the complete document:

```text
VAR X = <number>
VAR Y = VAR X
```

and resolves the chain transitively.  For the 4M document it returns exactly:

```text
GHTAY, OKOSG, QHUJP, AVCOU, INRCW
```

`scripts/needle_complex.py` decodes the document once when `--value-pick` is on,
runs this verifier only for VT questions, and appends the verified answer after
the model's answer.  The model's original reasoning is kept; the exact chain is
a deterministic retrieval/verification layer.
